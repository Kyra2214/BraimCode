# Fase 2 — Recurso de Estudo: Software Income Playbooks

## Referência

**Repositório:** `cporter202/software-income-playbooks`

**Tema:** playbooks de software, APIs selecionadas e caminhos de monetização para founders, agências e builders de automação.

## Por que entra na Fase 2

Este recurso complementa os catálogos técnicos de APIs já estudados pelo IaBrain com uma camada diferente: **capacidade técnica → oportunidade de produto → MVP → cliente → monetização → validação**.

O repositório organiza ideias práticas em torno de APIs e apresenta, entre outros elementos:

- cliente e problema;
- ideia de produto e MVP;
- APIs indicadas;
- modelo de monetização;
- ideias de preço;
- dificuldade de construção;
- tempo estimado para primeira versão;
- estratégia de entrada no mercado;
- riscos e limitações;
- adequação para SaaS, serviço productizado, automação, ferramenta interna ou produto de informação.

## O que o IaBrain deve estudar

### 1. Descoberta de oportunidades

Aprender a transformar uma capacidade/API descoberta em possíveis produtos:

`API → capacidade → problema → cliente → produto → MVP`

### 2. Avaliação comercial

Catalogar sinais como:

- valor do problema;
- público comprador;
- recorrência da necessidade;
- dificuldade de implementação;
- custo da API;
- margem potencial;
- velocidade para MVP;
- risco técnico/comercial;
- possibilidade de automação;
- possibilidade de transformar serviço manual em software.

### 3. Modelos de monetização

Estudar padrões como:

- assinatura;
- SaaS;
- serviço productizado;
- relatórios sob demanda;
- monitoramento e alertas;
- dashboards especializados;
- pesquisa premium;
- ferramenta interna para empresas/agências.

### 4. Composição de stacks

O repositório também é útil para estudar combinações de APIs que formam uma solução comercial, em vez de avaliar cada API isoladamente.

Exemplo conceitual:

`problema → APIs candidatas → workflow → MVP → agente/Skill → SandBox → resultado → validação → modelo comercial`

## Relação com o catálogo de APIs do IaBrain

O `software-income-playbooks` não deve ser tratado como fonte absoluta nem como dependência do sistema.

Ele deve complementar o catálogo interno:

`Catálogo de APIs → capacidade técnica → oportunidades → avaliação → teste → histórico → confiança`

O IaBrain poderá comparar uma oportunidade encontrada no playbook com:

- APIs realmente disponíveis;
- custos atuais;
- limites e autenticação;
- confiabilidade histórica;
- Skills existentes;
- agentes disponíveis;
- ferramentas do SandBox;
- resultados de testes próprios.

## Relação com o autoaprendizado

As experiências comerciais e técnicas podem alimentar a rede de aprendizado:

`Problema → API → estratégia → MVP → agente → Skill → execução → resultado → custo → tempo → qualidade → validação`

Com histórico suficiente, o IaBrain poderá aprender quais combinações têm maior probabilidade de produzir uma solução útil e viável.

## Relação com outros recursos da Fase 2

Este estudo complementa especialmente:

- `agentic-ai-apis` — descoberta de recursos agentic;
- `agentic-ai-starters` — workflows e arquiteturas;
- `job-data-apis-and-scrapers` — domínio especializado de dados de empregos;
- `LangChain` — ferramentas, integrações e padrões de agentes;
- `Matt Pocock Skills` — Skills reutilizáveis;
- demais catálogos de APIs e scrapers de `cporter202`.

A ideia é construir uma cadeia de conhecimento própria, e não depender de um único catálogo.

## Cuidados

O repositório informa que alguns links de APIs preservam rastreamento de afiliados. Portanto, o IaBrain deve registrar a procedência e manter avaliação independente da recomendação.

Além disso, preços, disponibilidade, limites e APIs podem mudar. Antes de transformar uma ideia em execução real, o IaBrain deve validar os dados atuais.

## Não fazer agora

- Não copiar o repositório para dentro do SandBox.
- Não transformar os playbooks em regras rígidas.
- Não assumir que uma API indicada continua disponível ou com o mesmo preço.
- Não confiar cegamente em uma recomendação comercial.
- Não misturar a camada de monetização com o cérebro/orquestrador.

## Princípio

> **O IaBrain não deve apenas descobrir como fazer algo. Ele deve aprender a avaliar se vale a pena fazer, para quem, com quais recursos, quanto custa e qual caminho apresenta melhor relação entre esforço, resultado e valor.**
